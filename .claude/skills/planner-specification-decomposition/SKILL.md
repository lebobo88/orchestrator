# Specification and decomposition

1. State the intended outcome, audience, explicit scope, exclusions, and success checks before listing work.
2. Decompose only into ordered, independently verifiable steps. Name the owner, dependency, and observable result for each material step.
3. Capture interface, data, compatibility, configuration, documentation, and operational impacts when evidence supports them.
4. Keep undecided alternatives as user decisions. Do not disguise recommendations or assumptions as requirements.
5. Include TDD-first acceptance checks for engineering and explicit Scribe targets for non-code deliverables.
