## Purpose

This ledger is the single persisted record of per-surface conformance against the Field Journal design system reference (`lizbeth_spanish\design\field-journal\Field Journal DS.dc.html`). It exists because the plan's "Why the prior 'validated' status is not evidence" section establishes that token/primitive conformance checks alone are not equivalent to a rendered-composition check against an artboard; this ledger tracks the composition-level check per surface, not the token-only check already recorded elsewhere (GitHub issues #31-#44).

Each row is updated by a follow-up `DOCUMENT_JOB` to Scribe after its owning work package completes verifier and browser-validator gates. Engineering writers do not edit this file directly.

## Method

Each surface is graded by one of two methods, per the plan's "Grounding and method" and "Visual comparison tolerance" sections:

1. **Composition checklist against an artboard**, for artboard-backed surfaces. A surface "matches" only if all six criteria in the plan's "Visual comparison tolerance" section hold: closed-palette color, correct named type-scale role, DS gap-family spacing, exactly one of the four border/shadow tiers, preserved composition order, and correct casing/tracking convention. A single-property deviation on criteria 1-4 is a fail regardless of pixel delta; no blanket pixelmatch percentage is used as the gate.
2. **No-artboard reviewer check**, for surfaces with no matching DS artboard (see the plan's "No-artboard composition table"). Each such surface is graded against its own named reviewer check (for example: "exactly one Primary control per view," "glyph+word status, not a bare color dot") rather than a visual diff, because no artboard exists to diff against.

**Tolerance and non-proof note:** a screenshot diff cannot prove font-hinting/antialiasing parity, real dynamic data against disclosed placeholders, scrollbar/OS-chrome rendering differences, or sub-pixel CSS-grid rounding. These are explicitly out of scope for a mismatch finding.

**Viewport profiles:** every artboard-backed surface and both chrome shells are checked at two Playwright CLI viewport profiles: **1440x900** (desktop) and **390x844** (mobile), matching the plan's DS section pairs (for example D.2 desktop / E.2 mobile).

**Browser-validation backend:** Playwright CLI only, per the plan's "Browser UI validation" section. `claude-in-chrome` and any Chrome-extension-based validation are explicitly out of scope for this plan.

**Environment note for later work packages:** `npm run test:e2e`'s default `webServer` (`netlify serve --context production`) fails locally because `scripts/verify-build-config.js` rejects a localhost `VITE_SUPABASE_URL`. Use `npx vite preview --port 8888` together with `E2E_BASE_URL=http://localhost:8888` instead of relying on the default `webServer` step.

**Artifacts:** each work package's browser-validation evidence (screenshots, Playwright output, journey transcripts) is stored under `browser-validation-artifacts/<wp>/` (for example `browser-validation-artifacts/wp-3/`), and each surface's "Fix evidence" cell in the table below links to the relevant files in that directory once its owning work package completes.

## Closure rule

A surface's status advances from `not started` only after both the verifier and the browser-validator have independently passed for its owning work package. An issue tied to a surface is closed only after that same condition holds, per the plan's binding closure rule (see "Ordered work packages," WP-0 section). For the shared WP-3/WP-4 anchor (issue `#42`, surfaces 18 and 19), the issue closes only after both WP-3 and WP-4 have independently passed verifier and browser-validator; the second package to finish performs the close and its comment references both packages' evidence.

This ledger's own status column is updated to reflect that same two-gate condition, not partial (writer-only) completion.

## Table field definitions

- **#**: surface number as enumerated in the plan's "Full 28-surface inventory" table. Stable across the life of this ledger.
- **Surface**: short name matching the plan's inventory.
- **Artboard reference**: the DS section/line citation the surface is graded against, or "no artboard" where the plan's no-artboard composition table and reviewer-check method apply instead.
- **Owning files**: source files exercised for this surface, matching the plan's inventory and per-surface specification sections.
- **Owning work package**: the WP (WP-1 through WP-14) responsible for this surface's remediation and browser-validation evidence.
- **GitHub issue**: the tracking issue number once WP-0 creates or reopens it, or "pending WP-0" before that package runs.
- **Status**: `not started`, `in progress`, or `closed` (closed only once both verifier and browser-validator have passed for the owning work package, per the closure rule above).
- **Elements/functions exercised**: the specific interactive elements, states, and functions the browser-validation journey actually drove for this surface.
- **Mismatches found**: composition or reviewer-check failures recorded during that surface's audit, cited by DS line or reviewer-check name.
- **Fix evidence**: links to `browser-validation-artifacts/<wp>/` screenshots/output, plus the verifier and browser-validator pass records, once the owning work package completes.
- **Notes**: open decisions, cross-cutting gaps, recorded resolutions, or other context specific to that surface.
